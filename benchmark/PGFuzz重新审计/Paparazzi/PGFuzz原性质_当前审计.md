# Paparazzi：PGFuzz 原 5 条性质的当前审计

## 术语、版本与审核边界

- `MTL` 是 Metric Temporal Logic，中文为“度量时序逻辑”；它用时间区间描述状态随时间必须怎样变化。`MITL` 是 Metric Interval Temporal Logic，中文为“度量区间时序逻辑”，要求时间约束使用非零长度区间。本文件保留论文的 MTL 原式；当前改写没有可靠有限上界时保持无界，不人工补秒数。
- `AP` 是 Atomic Proposition，中文为“原子命题”，即公式中每个可以单独判真假的最小条件。`t-1` 是同一运行、同一坐标系中的上一条有效观测，不是一秒前。
- `PPRZLink` 是 Paparazzi 原生通信协议；冻结的官方 Bebop2 配置默认使用它。`MAVLink` 是 Micro Air Vehicle Link，中文为“微型飞行器通信协议”；Paparazzi 有可选实现，但冻结配置没有启用，因此不能把可选 MAVLink 消息冒充默认运行观测。
- `ENU` 是 East-North-Up，中文为“东—北—天”局部坐标；`NED` 是 North-East-Down，中文为“北—东—地”局部坐标。比较前后位置或高度时必须保持同一坐标系和同一原点。
- PGFuzz 的状态分类：`S1` 为位置状态，`S2` 为姿态状态，`S3` 为飞行运行状态，`S4` 为遥控输入，`S5` 为系统状态，`S6` 为传感器状态。`InputP`、`InputC`、`InputE` 分别是配置参数、用户命令和环境因素；公开 PGFuzz 制品没有 Paparazzi 的性质输入目录，所以不能补造作者依赖。
- 源码绑定只回答“状态在当前源码哪里定义、更新、使用、怎样观测”，不从实现反推出规范，也不判断整条性质是否满足。全部性质固定为“实现符合性：未评估”。

冻结基线：Paparazzi 提交 `b51490c88bf972b764229d5f034957a41b6ce57c`；官方 `Bebop2`、`rotorcraft_basic.xml` 飞行计划、`nps` 仿真目标。配置入口见 [`conf/conf_example.xml:2-10`](https://github.com/paparazzi/paparazzi/blob/b51490c88bf972b764229d5f034957a41b6ce57c/conf/conf_example.xml#L2-L10)。

## 参数、可修改性与作者依赖结论

- 论文五条 Paparazzi 性质没有公开 `parameters.txt`、`cmds.txt`、`envs.txt`、`preconditions.txt`，所以作者候选依赖统一为“公开制品未提供”。这不是“没有依赖”，而是“无法从公开制品确认”。
- `NAV_CLIMB_VSPEED=4.5` 米/秒、Takeoff 阈值 `2.0` 米、`MAX_DIST_FROM_HOME=150` 米来自冻结 XML 配置，改变并重新生成/编译配置即可变化；它们不是运行中通过 MAVLink 参数协议任意修改的 ArduPilot/PX4 风格参数。
- `autopilot.mode`、`guidance_h.mode`、`guidance_v.mode` 是运行状态，不是配置参数。`ROTORCRAFT_STATUS` 只报告它们，不代表地面端能安全写入全部状态。

## 校勘结论

论文五条均不能原样当作当前 Bebop2 规范：三条 Hover 性质忽略了当前水平/垂直引导拆分和遥控前提；Takeoff 的自然语言与公式方向冲突且冻结任务使用 2 米配置阈值；HOME1 把“目标设为 HOME”过强地写成每个采样点都必须变化并暗含最终着陆。当前改写只保留有明确文档、配置或规范性注释证据的部分；控制流仅用于源码身份对应。
