固件模糊测试：最新技术
ACM
Chi Zhang
背景：固件是物联网 （IoT） 设备的使能软件，其软件漏洞是物联网设备被利用的主要原因之一。由于 IoT 设备的资源有限，部署复杂的运行时保护技术是不切实际的。在不安全的网络环境下，当固件被利用时，可能会导致拒绝服务、信息泄露、权限提升，甚至危及生命。因此，通过模糊测试进行固件漏洞检测成为保证物联网设备安全的关键，也成为学术和工业研究的热点。随着现有 IoT 设备的快速增长、固件的大小和复杂性、固件类型的多样性以及固件缺陷，现有的 IoT 固件模糊测试方法面临挑战。目的： 本文总结了典型的物联网固件模糊测试方法类型，分析了这些工作的贡献，并总结了现有模糊测试方法的不足。方法： 我们设计几个研究问题，从研究问题中提取关键词，然后使用关键词搜索相关文献。结果： 我们根据固件执行环境，将现有的固件模糊测试工作分为基于 realdevice 的模糊测试和基于仿真的模糊测试，基于仿真的模糊测试是未来的主流;我们发现，现有模糊测试方法针对的漏洞类型主要为内存损坏漏洞;固件模糊测试比普通软件模糊测试面临更多的困难。结论： 通过分析不同方法的优缺点，本文为进一步提高模糊测试技术的性能提供了指导，并根据本综述的结果提出了几项建议。

1 介绍
近年来，硬件计算能力的提高、通信速度的加快以及通信方式的增加为物联网 （IoT） 设备提供了更多的应用场景。目前，IoT 设备数量保持快速增长态势，但针对 IoT 设备的攻击数量也增长得更快。例如，犯罪分子使用 IoT 设备在 Github 上制造了历史上最大的拒绝服务攻击 [25]。因此，学术界和工业界都越来越重视检测 IoT 固件中的漏洞，IoT 设备已成为许多研究人员的热点。IoT 设备中的固件是指 IoT 设备中的所有软件。固件测试的方法有很多，如静态分析 [11]、符号执行 [14]、模糊测试 [57]、基于机器学习的漏洞预测 [54] 等，但模糊测试是研究最多的方法之一。
模糊测试是指向程序提供大量正常和异常测试用例，并监控程序的状态以检测异常的方法 [37]。生成测试用例主要分为两类：基于生成的方法和基于突变的方法。基于生成的方法通过对软件的输入格式、运行时环境和通信协议进行建模来生成符合规范的测试用例。这类作品很多，其中著名的有桃子[18]、萨利[2]、MoWF[42]等。基于突变的方法通过将突变操作应用于现有的有效测试用例来生成新的测试用例。经典作品如 AFL [27]、Honggfuzz [49]、BuzzFuzz [22] 等。模糊测试在应用程序级软件测试中产生了有希望的结果，因此这种方法已经扩展到许多领域，如内核测试（例如，Syzkaller [26]）、固件测试（例如，FIRM-AFL [57]）、协议模糊测试（例如，Autofuzz [28]）等。
本文的组织如下：本综述中使用的研究方法在第 2 节中详细讨论，然后，回答研究问题的综述结果在第 3 节中介绍。第 4 节讨论了固件模糊测试的缺陷和未来的改进。最后，第 5 节总结了该评论。

3 结果
从选定的原始研究中提取数据后，进行数据合成。我们总结了现有的工作来回答我们的问题。
3.1 基于仿真的模糊测试是未来的主流。（RQ1）
受益于硬件计算能力的提高和通信速度的加快，以及通信技术的增加，物联网设备的类型和形式正在迅速增长。例如，物联网设备的 CPU 架构包括 ARM、MIPS、X86 等。片上外设包括 I2C、USART、GPIO 等。片外外设包括无线、蓝牙、ZigBee、陀螺仪、温度计等。CPU 架构类型和外设类型的快速增长给 IoT 设备的仿真带来了很大的困难。因此，早期的固件模糊测试是在真实设备上进行的。RPFuzzer [53] 通过向真实的路由器设备发送普通数据包来检测路由器协议中的漏洞，同时监控路由器的 CPU 利用率并检查系统日志以检测 DoS 漏洞和路由器重启。IOTFuzzer [10] 通过分析移动应用与 IoT 固件的交互来获取 IoT 固件通信协议中的信息，并根据这些信息生成测试用例。此过程不需要获取 IoT 设备的固件。Asadollah 等人 [4] 在嵌入式操作系统 FreeRTOS [1] 中自动收集事件信息，并确定是否存在并发漏洞。但这项工作的重点是嵌入式操作系统。
基于真实设备的模糊测试可以获取设备最真实的执行信息，但仍然存在很大的约束。首先，可用的执行信息是有限的。商用 IoT 设备通常不为用户提供调试接口，因此无法获取具体的运行时信息，例如执行路径。其次，在真实环境中，很多极端情况都难以构建，因此难以提高模糊测试的代码覆盖率，这是评价模糊测试技术质量的主要指标之一。最后，测试需要获取大量的真实设备，并手动连接和调试，这需要大量的经济和时间成本。基于仿真的模糊测试可以解决上述问题，成为当前研究的主流。目前主流的虚拟平台包括 QEMU [6] 和 Simics [46]。QEMU 因其开源和易用性而成为学术研究的热点。然而，由于模拟器模拟外设的能力不足，目前的研究重点是使用不同的方法来弥补这一不足。
Avatar [56] 通过在模拟器中执行代码，在真实设备中执行 I/O 操作，解决了模拟器无法模拟外设的问题。SURROGATES [35] 基于 Avatar，提高了模拟器和硬件之间的通信能力。Avatar2 [40] 具有更强大的编排能力，允许不同的分析框架、调试工具、模拟器和真实设备相互交互。FIR-MADYNE [9] 基于 QEMU 的完整系统仿真和插桩内核，以实现在模拟器中对网络连接的商业现成设备的基于 Linux 的固件进行模糊测试的能力。FIRM-AFL [57] 并协调 QEMU 的全系统仿真和用户态仿真，以提高模拟器性能。FirmAE [34] 允许 FIRMADYNE 模拟更多固件。Laelaps [7] 使用共控执行通过约束求解生成合格的外设输入，以弥补仿真器无法仿真外设且不需要任何固件知识。它还对基于 ARM Cortex-M 的嵌入式微控制器的某些部分进行建模，这是必不可少的，但缺少完整的系统仿真。P2IM [19] 和 DICE [39] 对外围设备进行建模，以生成保持固件平稳运行的外设输入。HALucinator [12] 通过替换硬件抽象层 （HAL） 代码将硬件与固件解耦，然后模拟器可以无障碍地模拟外围设备。
3.2 内存损坏漏洞是主要检测目标。（RQ2）
基于实机的模糊测试只能获取有限的信息，因此无法判断漏洞的确切类型和具体位置。RPFuzzer [53] 监控 CPU 利用率以检测 DoS 漏洞，向路由器发送正常消息，并分析系统日志以检测系统崩溃、重启和僵尸进程。
IOTFuzzer [10] 旨在查找 IoT 设备中的内存损坏漏洞，并通过发送心跳消息来推断设备的活跃度。Asadollah 等人 [4] 使用 Tracealyzer 工具记录相关事件并推断是否存在并发漏洞。
Avatar [56]、SURROGATES [35] 和 Avatar2 [40] 作为编排框架的目的是使不同的工具能够相互交互，它不具备检测漏洞的能力。FIRMADYNE [9] 和 FirmAE [34] 实现了自动动态分析传递，这些传递被注册为回调，以检测漏洞，包括信息泄漏、缓冲区溢出和命令注入等。FIRM-AFL [57]、Halucinator [12]、P2IM [19] 和 DICE [39] 使用 AFL [27] 作为模糊测试程序，并根据崩溃情况判断是否存在内存损坏漏洞。Laelaps [7] 基于 Muench 等人 [41] 的工作，并使用 PANDA [36] 插件检测六种类型的内存损坏漏洞。
这些模糊测试工具检测到的漏洞信息列在附录 A 的表 1 中。通过对比，我们发现基于 realdevice 的模糊测试所能获得的运行时信息是有限的，因此很难找到漏洞的确切类型和位置。基于仿真的模糊测试可以通过 pass 或 QEMU/PANDA 插件获取更详细的固件运行时信息，例如执行路径、指令和变量值。这种情况具体反映在 FIRMADYNE [9] 和 Laelaps [7] 的作品中。在这个阶段，工作仍然集中在弥补模拟硬件中模拟器的不足。因此，许多工作并不关注寻找漏洞，而是使用模糊代码覆盖率中的另一个重要维度来表示它们从外围设备生成输入的能力。
3.3 固件模糊测试比一般的软件模糊测试面临更多的困难。（RQ3）
因为固件的执行环境与一般软件不同，所以模糊测试的难易程度存在一些差异。首先，获取二进制文件的难度不同。当我们对我们有权使用的通用软件进行模糊测试时，我们绝对可以获取它的二进制文件甚至源代码。但是在固件测试中，情况就完全不同了。固件存储在嵌入式设备中，并与设备一起出售。固件升级可以完全自动化，无需从网站额外下载。用户没有足够的工具和功能来从设备中提取固件。制作没有稻草的砖头，但 IOTFuzzer [10] 提出了一种无需获取设备中固件即可直接与设备交互的方法，解决了物联网设备与移动应用交互时的通信加密问题。
其次，固件的执行环境很难构建。通用软件模糊测试在运行时通过编译时的插桩或通过硬件辅助（如 IntelPT [32]）获取特定信息。基于实际设备的模糊测试可以以足够快的速度运行，但无法获得足够的运行时信息。幸运的是，Arm Cortex-M 微控制器中有一个调试组件 ETM [3]，它的功能类似于 IntelPT，可以用来跟踪固件的执行路径，但这个功能需要特定的物理接口和调试工具 J-Trace [47]。基于仿真的模糊测试可以获得足够的运行时信息，但无法达到一般软件模糊测试的速度。FIRM-AFL [57] 结合了全系统仿真和用户态仿真，以提高仿真的性能，但它仍然无法与实际执行相提并论。
第三，固件二进制文件比一般软件更复杂。由于 IoT 设备的底层硬件架构更加丰富，因此固件二进制指令集比一般软件更复杂。并且固件需要考虑与底层硬件的交互，这对于一般软件来说是不必要的。这些挑战在集成静态分析、符号执行和其他技术时造成了巨大的障碍。例如，符号执行需要适应特定的指令集和内存架构。Laelaps [7] 适配于 Arm Cortex-M 系列处理器的符号执行。
第四，固件输入比一般软件更复杂。固件的外设输入可以分为两类。一种是来自感知层的外围输入，如麦克风、摄像头、重力传感器、温度传感器、陀螺仪等。这种类型的外设输入主要基于图像、声音和数值，最后以数字形式写入内存。这个 input 的构造需要一些特定外设的领域知识，比如视频编解码等。但是一般软件的模糊测试不需要考虑这些，只提供视频、图片等信息作为测试用例给软件。另一种是来自传输层的通信外设输入，如无线、蓝牙、ZigBee 等。这些外设输入主要以数据包的形式出现，需要以字符串的形式写入内存，但这种类型的输入往往包含状态，输入的结构需要对通信协议和设备使用环境进行建模。这种类型的外设输入类似于一般软件的协议测试。固件中的另一个重要输入是中断。这种输入在一般软件中相对较少。要确定其输入时间和输入值，需要对代码和使用环境进行深入分析。Laelaps [7]、P2IM [19] 和 DICE [39] 都添加了对模糊测试中断的支持。
4 讨论
随着物联网设备数量的爆炸式增长以及物联网设备在生产和生活重要领域的逐渐应用，物联网设备的安全性已成为学术界和工业界的研究热点。现有的模糊测试工具已用于商业物联网设备。在物联网设备中发现了许多漏洞，但相对于大量 IoT 设备，这些任务只是九牛一毛。目前的学术研究远非商业应用。这有很多原因。
首先，获得固件的难度限制了研究人员在该领域的工作。在这种情况下，安全研究人员只能使用有限的调试和测试方法，或者使用侧信道攻击等其他技术来发现物联网设备中的漏洞，但这些技术很难发现隐藏在固件中的漏洞，无法有效保证固件安全。如果将来研究人员可以使用固件基准测试，则可以节省研究人员构建数据集的时间，提供统一的测试标准，最终促进固件测试的发展。
其次，模拟器的缺乏限制了研究过程。通过研究，在基于实器件的模糊测试中很难发现更多类型的漏洞，基于仿真的模糊测试将是未来的主流。仿真器的能力是限制基于仿真的模糊测试效果的主要因素，但现有的仿真器在仿真不同的硬件时仍然存在很大的限制。手动修改模拟器以添加对其他硬件的支持是一项困难且耗时的工作，并且会影响工具的可扩展性。如果模拟器将来可以轻松兼容新硬件，则可以使研究人员专注于解决测试方法本身的问题。
此外，当前基于仿真的模糊测试并未充分利用从模拟器获取的丰富信息来判断是否存在漏洞。许多工作仍然依赖于检查系统状态来确定是否存在漏洞 [12,57]。相反，SDRacer [51,52] 试图利用虚拟平台来检测错误，同时监控系统的运行时信息。此外，Laelaps [7] 已经证明 PANDA 插件足以检测更多漏洞。这些技术作为提高模糊测试有效性的一种有前途的方法，可用于检测更复杂和更关键的软件漏洞。未来，漏洞检测可以作为一项单独的工作来完成，以插件的形式集成到仿真平台中，以提高模糊测试工具的漏洞检测能力。此外，未来的工作可以将漏洞检测能力作为反映能力质量的主要标准，因为在很多情况下，物联网设备在遇到漏洞时不会崩溃。
最后，目前的工作没有考虑物联网设备的使用环境和各种通信协议。虽然目前的工作使用了各种方法，如外设建模，结合符号执行，来提高模糊测试的代码覆盖率，但这些方法生成的外设输入并不具有实际意义，并且基于状态的外设输入很难通过这些方法生成。只有考虑物联网设备的使用环境和固件与外界交互的协议，才能产生更有意义的输入，更有效地提高代码覆盖率。因此，在未来的工作中，可以考虑通过对通信协议进行建模来有效地生成输入。
5 结论
本文献综述的主要目的是总结现有的 IoT 模糊测试技术，以识别现有的软件漏洞、最先进的模糊测试技术和性能评估。此外，根据定义的研究问题，从本文献综述中获得的主要发现总结如下。
我们根据固件执行环境，将现有的固件模糊测试工作分为基于实设备的模糊测试和基于仿真的模糊测试，两种模糊测试方法解决的问题不同。基于实车的模糊测试主要关注如何与真实设备进行交互，并获取设备的状态，从而判断是否触发了漏洞。此类方法无法获取漏洞的确切位置和类别。基于仿真的模糊测试侧重于解决仿真平台无法兼容外围硬件的问题，并生成有效的测试用例，以提高模糊测试的代码覆盖率。基于模拟的模糊测试可以获得更丰富的运行时信息，以辅助漏洞检测。
由于目前的研究重点仍然在解决固件执行环境或交互方法上，因此现有的工作并不将检测更多类型的漏洞作为其主要目标。在基于实点的模糊测试中，设备执行日志和设备运行时状态是判断漏洞是否触发的主要因素。检测的漏洞主要为内存损坏漏洞或设备崩溃相关漏洞。在基于仿真的模糊测试中，大多数工具使用 AFL [27] 作为模糊测试器，并将系统是否崩溃视为触发内存损坏漏洞的因素，但模拟器可以提供更丰富的运行时信息。只有 FIRMADYNE [9] 和 Laelaps [7] 使用此信息来检测其他类型的漏洞。
固件模糊测试和一般软件模糊测试之间存在巨大差异。固件的二进制文件难以获取，测试环境难以搭建，固件代码较复杂，固件测试用例难以生成。通用软件模糊测试工具仅部分用于固件模糊测试的 AFL [27]。其他工具很难应用于固件模糊测试。由于固件所在硬件设备的架构复杂，很难将静态分析、符号执行等传统分析技术集成到模糊测试中，以提高测试效率。
目前的模糊测试技术无法大规模应用于商用物联网固件。因此，我们提出了未来的研究建议。完整的 IoT 固件测试基准有利于固件测试研究;完整的仿真环境有助于研究人员专注于解决模糊测试本身的问题;充分利用从模拟器中提取的固件运行时信息有助于发现更多类型的漏洞;充分考虑物联网设备的场景信息和通信协议信息，有助于提高模糊测试效率。
